# 寻迹 · 产品设计案例网站

XUNJI 是一款本地优先的收纳 App，帮你记住有什么、放在哪、什么时候到期。这个仓库是它的设计案例展示网站，一个纯静态单页站点，默认中文，可切换英文。

## 页面结构（按路演顺序）

1. **首页**：从真实痛点切入的标题与三张 App 截图；点击截图打开翻页式演示
2. **开场共鸣与痛点引入**：官方调查数据（Pixie Lost & Found Survey，2016.10，样本 1,700+，来源 PR Newswire）+ 我们 6 位受访用户的原话
3. **产品演示与流程展示**：概念演示入口、三个核心界面、五步设计流程
4. **调研与问题定义**：问卷 / 市面产品 / 用户访谈三层调研、人物画像「小林」、问题从「帮人找到东西」收窄到「帮用户找到重要但常用的东西」
5. **规划与测试迭代**：软硬件联动初始草图 → 第一版模型用户测试 → 真实反馈 → 2.0 / 3.0 一屏一屏拖拽对比
6. **硬件方案**：仅保留大框架占位，具体方案待补充

数据来自《寻迹APP用户体验测试表》《寻迹APP用户体验测试汇报》与《寻物产品路演思路指导》。测试于 2026-11-22 完成，汇报人：易千惠、张婉清、丁紫妍。官方数据均标注来源，未使用编造数字。

问卷星统计 PDF 已接入页面（116 份有效回答）。待补充：硬件方案定稿。

## 本地预览

直接用浏览器打开 `index.html` 即可，无需构建或安装依赖。若希望模拟线上环境，可在目录内启动任意静态服务器，例如：

```bash
python -m http.server 8000
```

然后访问 `http://localhost:8000`。

## 文件结构

```
.
├── index.html    # 页面结构、文案与内嵌截图（图片已 base64 内嵌，无外部路径依赖）
├── styles.css    # 主题、全部样式与响应式
├── script.js     # 中英切换、主题切换、对比拖拽、翻页展示、滚动交互
├── assets/       # 截图原图备份（可选，不上传也不影响网站显示）
└── README.md     # 本文件
```

## 部署到 GitHub Pages

1. 新建公开仓库，例如 `xunji-case`（仓库名建议用英文，不带空格）。
2. 把 `index.html`、`styles.css`、`script.js`、`README.md` 上传到仓库根目录。`assets/` 文件夹是原图备份，可传可不传——所有截图已内嵌到 `index.html`，不传也能正常显示。
3. 进入仓库 **Settings → Pages**，Source 选择 `main` 分支 / `root`，保存。
4. 等待 1–2 分钟，访问 `https://<用户名>.github.io/<仓库名>/`。

站点为纯前端，无后端、无构建步骤。语言选择会保存在浏览器本地存储中，首次访问默认中文。
